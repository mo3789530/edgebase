# Requirements: Local DB OTA

## 1. Schema Management (Control Plane)

*   **REQ-1.1**: システムは、SQL形式のマイグレーションファイルをバージョン番号付きで保存できなければならない。
*   **REQ-1.2**: システムは、アップロードされたSQLの基本的な構文チェックを行うことが望ましい。
*   **REQ-1.3**: システムは、登録されたスキーマの一覧と詳細を提供しなければならない。

## 2. Update Delivery (Communication)

*   **REQ-2.1**: Control Planeは、新しいスキーマが登録された際、関連するエッジノードに更新通知（MQTT推奨）を送らなければならない。
*   **REQ-2.2**: エッジノードは、通知を受信した際、または定期的なチェック時に、自身のバージョンとサーバーの最新バージョンを比較しなければならない。
*   **REQ-2.3**: 通信は認証され、改ざん防止（HTTPS/TLS）がなされていなければならない。

## 3. Migration Execution (Edge Agent)

*   **REQ-3.1**: エッジエージェントは、適用されていないマイグレーションをバージョン順（昇順）に適用しなければならない。
*   **REQ-3.2**: マイグレーションの適用は**原子的（Atomic）**でなければならない。失敗した場合は完全に元の状態に戻らなければならない。
*   **REQ-3.3**: エッジエージェントは、適用済みバージョンをローカルDB内の管理テーブル（例: `_schema_migrations`）に記録しなければならない。

## 4. Status Reporting & Monitoring

*   **REQ-4.1**: エッジエージェントは、マイグレーションの成功・失敗の結果をControl Planeに報告しなければならない。
*   **REQ-4.2**: 失敗した場合、エラーメッセージを含めて報告しなければならない。
*   **REQ-4.3**: Control Planeは、全ノードのスキーマ適用状況（バージョン分布、失敗ノード一覧）を確認できるAPIを提供しなければならない。
