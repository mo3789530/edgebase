# EdgeBase MVP Features

EdgeBase を集約型 Control Plane + 集約型 DB で成立させるための、MVP 時点で必要な機能一覧。

このドキュメントでは、機能を `MVPで必須` と `Phase 2で拡張` に分ける。

## MVPで必須

### 1. 認証・認可

目的:
- ユーザー、管理者、ノード、内部サービスを区別する
- 保護対象 API へのアクセス制御を行う

最低限必要な要素:
- ユーザー向け認証
- ノード向け認証
- ロール分離 (`admin`, `developer`, `operator`, `node`, `service`)
- リソース単位の認可
- トークン失効

MVP要件:
- JWT または API key
- 認証主体ごとの claims 分離
- 保護 API への middleware 適用

### 2. マルチテナント管理

目的:
- 集約型 DB 上で organization / project 単位にデータを分離する

最低限必要な要素:
- `organizations`
- `projects`
- `memberships`
- リソースへの `tenant_id` または `project_id`

MVP要件:
- 主要テーブルに tenant 境界を持たせる
- 権限判定で tenant 境界を必ず考慮する

### 3. API Gateway

目的:
- すべての API リクエストの入口を一元化する

最低限必要な要素:
- 認証
- レート制限
- 監査入口
- ルーティング
- request ID 付与

MVP要件:
- Control Plane API の共通 middleware
- 保護 API と公開 API の明確な分離

### 4. オブジェクトストレージ

目的:
- WASM アーティファクト、ログ、バックアップを格納する

最低限必要な要素:
- Artifact upload/download
- バージョン付き保存
- ストレージ抽象化

MVP要件:
- MinIO または S3 対応
- アーティファクトの参照情報を DB に保存

### 5. ノード管理プレーン

目的:
- エッジノードの登録から運用状態の把握までを担う

最低限必要な要素:
- ノード登録
- ハートビート
- 状態監視
- 失効

MVP要件:
- ノードを一意に識別できる
- オフライン判定のための heartbeat 情報がある
- 失効したノードを遮断できる

### 6. デプロイ管理

目的:
- 関数の配布、反映、ロールバックを行う

最低限必要な要素:
- デプロイ要求
- 配布対象ノード指定
- 配布状態の追跡
- ロールバック

MVP要件:
- Function version を扱える
- ノードごとの deployment 状態を保持できる

### 7. 同期エンジン

目的:
- エッジと中央の状態差分を同期する

最低限必要な要素:
- 同期計画生成
- ACK
- 差分判定
- 競合時の方針

MVP要件:
- schema / function 配布の差分同期
- 同期履歴の保存

### 8. ルーティング / サービスディスカバリ

目的:
- リクエストを適切な function / node に解決する

最低限必要な要素:
- Route 定義
- host/path/method 解決
- POP / node 選択

MVP要件:
- route の作成・一覧取得
- edge runner 側で route を解釈できる

### 9. 監査ログ

目的:
- 誰が何をしたかを追跡する

最低限必要な要素:
- actor
- action
- resource
- status
- timestamp

MVP要件:
- 関数登録、更新、削除、デプロイ、認証イベントの記録

### 10. メトリクス / ログ

目的:
- 障害時に原因を追跡し、状態を可視化する

最低限必要な要素:
- request metrics
- application logs
- request_id

MVP要件:
- API 単位のメトリクス
- 構造化ログ

### 11. シークレット管理

目的:
- JWT secret、ストレージ鍵、外部 API 鍵を安全に扱う

最低限必要な要素:
- 本番用 secret 配布方法
- ローテーション方針
- 平文保存の回避

MVP要件:
- `.env` 依存のみで本番運用しない
- secret の責務分離を定義する

## Phase 2で拡張

### キュー / 非同期ジョブ

- デプロイ通知
- 集計処理
- 再試行制御

### ジョブ再試行 / デッドレター

- 一時障害時の再試行
- 永続失敗時の隔離

### トレース

- Control Plane -> Edge -> Function 実行の相関追跡

### 設定管理

- 環境差分
- ノード単位設定
- feature flag

### 証明書更新 / mTLS

- ノード証明書の配布
- 更新
- 失効

## 実装順の推奨

1. 認証・認可
2. マルチテナント管理
3. ノード管理プレーン
4. デプロイ管理
5. 同期エンジン
6. API Gateway
7. 監査ログ
8. オブジェクトストレージ
9. メトリクス / ログ
10. シークレット管理
11. キュー / 非同期ジョブ
12. ジョブ再試行 / デッドレター

## 補足

- 集約型 DB を採る場合、マルチテナントは後付けしない方がよい。
- 認証と監査ログはセットで導入する。
- 同期エンジンとジョブ基盤は責務を分離する。
